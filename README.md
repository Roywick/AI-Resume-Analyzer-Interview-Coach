# ResumeIQ AI — AI Resume Analyzer & Interview Coach

A full-stack AI SaaS app: upload a resume, get an ATS score and job-match breakdown,
improve it with AI, rehearse with an interview coach, and generate a tailored cover
letter — all in one session, with **no database and no accounts**. Nothing you upload
is ever persisted.

## Tech stack

**Frontend:** React 18, Vite, React Router DOM, Tailwind CSS, Framer Motion, React Hook Form, Axios, Recharts, lucide-react, jsPDF
**Backend:** Node.js, Express
**AI:** Google Gemini API (`@google/generative-ai`, `gemini-1.5-flash`)
**File handling:** Multer (in-memory only), pdf-parse, mammoth

## Local setup

### 1. Backend

```bash
cd server
cp .env.example .env
# edit .env and add your GEMINI_API_KEY (from https://aistudio.google.com/apikey)
npm install
npm run dev
```

The API runs on `http://localhost:5000` by default.

### 2. Frontend

```bash
cd client
cp .env.example .env
npm install
npm run dev
```

The app runs on `http://localhost:5173` and proxies `/api/*` requests to the backend
during development (see `vite.config.js`).

## API reference

All AI endpoints return JSON generated by Gemini and are rate-limited (60 requests /
15 min per IP) since each call costs money against your Gemini quota.

| Method | Endpoint | Body | Description |
|---|---|---|---|
| POST | `/api/resume/upload` | `multipart/form-data`, field `resume` (PDF/DOCX, ≤8MB) | Extracts and returns resume text |
| POST | `/api/analysis/resume` | `{ resumeText }` | ATS score, strengths/weaknesses, readability, detected skills |
| POST | `/api/analysis/job-match` | `{ resumeText, jobDescription }` | Match %, missing skills/keywords, suggestions |
| POST | `/api/analysis/improve` | `{ resumeText, jobDescription? }` | Rewritten summary, action verbs, before/after |
| POST | `/api/interview/generate` | `{ resumeText, jobDescription?, targetRole? }` | HR/technical/behavioral/project questions with sample answers |
| POST | `/api/cover-letter/generate` | `{ resumeText, jobDescription?, targetRole? }` | Full cover letter body |
| POST | `/api/chat/message` | `{ message, history?, resumeText?, jobDescription?, targetRole? }` | Reply from the "Ask ResumeIQ" chat widget |
| GET | `/api/health` | — | Health check |

**Error shape** (all 4xx/5xx responses):
```json
{ "error": "Short error type", "message": "Human-readable explanation" }
```

## Deployment

### Backend → Render
1. Push this repo to GitHub.
2. New **Web Service** on Render, root directory `server/`.
3. Build command: `npm install` · Start command: `npm start`.
4. Add environment variables: `GEMINI_API_KEY`, `CLIENT_ORIGIN` (your Vercel URL), `PORT` (Render sets this automatically — you can omit it).

### Frontend → Vercel
1. New Project on Vercel, root directory `client/`.
2. Framework preset: Vite. Build command: `npm run build`. Output directory: `dist`.
3. Add environment variable `VITE_API_PROXY` pointing at your Render backend URL, **or**
   update `src/services/api.js`'s `baseURL` to the full backend URL (`https://your-api.onrender.com/api`) for production, since Vite's dev proxy doesn't apply to the built app.

## Notes on the "no database" requirement

- The frontend keeps all session state (resume text, analysis results, etc.) in a
  React Context that lives only in memory — refreshing the page clears it.
- The backend's Multer middleware uses **memory storage**, not disk storage: the file
  buffer is parsed for text and then garbage-collected. Nothing is written to
  `server/uploads/` (that folder is kept only as a placeholder via `.gitkeep`).
- There are no user accounts, sessions, cookies, or auth middleware anywhere in the app.

## What's built vs. what to extend

Fully implemented: landing page, all 11 routes, full session flow (upload → analyze →
ATS report → job match → improve → interview coach → cover letter → PDF export), dark
mode, responsive layout, loading/skeleton states, and all 6 backend endpoints wired to
Gemini with structured-JSON prompts.

Worth extending for a production launch: automated tests, request logging/observability,
a real email service for the Contact page (currently simulates a send client-side),
and a virus/malware scan step on uploaded files before parsing.
